# huhucapture v0.0.6 — Windows 更新桥

这一版本继续提供 Windows x64 原生单 EXE，为现有用户准备通向后续 Qt 完整包的下载路径。Qt Windows / Linux 首发目标仍为 v0.1.0；本次不包含 Qt 界面、Qt 动态库、Linux 包或新安装器，也不声明这些产品已经完成安装验收。

## 更新能力

- “设置 → 关于 → 下载最新版本”识别正式 Release 的完整包清单，选择 Windows x64 便携 ZIP，并核对版本、仓库、架构、依赖清单、长度和 SHA256。
- 完整包流式写入系统实际 Downloads，支持超过旧 64 MiB 上限的包；不把整个包读入内存。
- 没有完整包清单的旧 Release 继续下载已核验的单文件 EXE。有清单但损坏或下载失败时明确报错，不降级为可能缺依赖的裸 EXE。
- 下载完成后显示实际路径及完整包解压说明，六种语言均保留这些说明。关闭关于页不会中断服务任务，重新打开可查看当前状态；退出程序取消并回收网络任务。
- 重名下载产生新名称，失败只清理本次暂存文件；不自动执行、覆盖正在运行的程序、重启或删除 Documents 媒体。

## 从 v0.0.5 升级

当 v0.0.6 仍是 latest 时，在 v0.0.5 的关于页下载最新版本即可取得本次 `huhucapture.exe`。退出旧程序后，将下载文件改名为原程序名并手动替换；保留原有配置和媒体目录。

本次发行仍只有五项原生 Windows 资产：`huhucapture.exe`、便携 ZIP、同次构建符号 ZIP、`build-info.json` 和 `SHA256SUMS.txt`。软件使用者下载 EXE 或便携 ZIP 即可；符号 ZIP 用于故障定位。

## 后续 Qt 完整包

Qt 版成为 latest 后，v0.0.6 能从其正式清单下载完整 ZIP。退出旧程序，将整个 ZIP 解压到新目录，保留旧目录和原配置。若原来使用 EXE 旁的便携 `config.json`，在第一次运行新包前将其复制到新 EXE 旁，保留旧原件；按该 Qt 版本说明核对系统支持与配置迁移。不要单独抽出新 EXE，也不要清理 Documents 中已有媒体。

**跳过桥接的 v0.0.5 不会自动回溯历史 Release。** Qt 成为 latest 后，请直接打开 [最新正式发行](https://github.com/NAMEWTA/huhucapture/releases/latest)，从 Assets 下载完整 Windows 安装器 `huhucapture-vX.Y.Z-windows-x64-setup.exe` 或便携包 `huhucapture-vX.Y.Z-windows-x64.zip`。这一手动路径不要求先安装桥接，也不把旧裸 EXE 放到 Qt tag 下冒充兼容。

## 验证范围

独立发布要求同一 main 提交通过原 Windows Release / Debug、核心规则、原生渲染、托盘、真实 GUI / 剪贴板、真实 latest 下载和打包验证，还要求生产 WinRT 下载器在 Debug / Release 下完成受控完整包下载、错误拒绝、取消、重名保护和真实关于页六语检查。受控 ZIP 明确不是可安装 Qt 产品；这组证据不代替 Qt 双平台构建、安装、升级、卸载或实体设备验收。实际运行结果和发行字节以本次 Actions、build-info 与 SHA256 为准。
