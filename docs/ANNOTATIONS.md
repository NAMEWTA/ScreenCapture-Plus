# 批注工具与合并导出

批注用于把截图上的位置与右侧说明关联起来。工具条在普通“序号”旁提供独立的“批注”：点击图片放置彩色编号，选中 pin 或列表项后在右侧编辑说明。保存和复制输出一张包含原图、活动图形及全部批注说明的图片。

## 交互与普通序号的区别

| 行为 | 普通序号 `ShapeNumber` | 批注 `ShapeAnnotation` |
| --- | --- | --- |
| 内容 | 图中的序号形状 | 图中编号 pin 与所属完整备注 |
| 颜色 | 沿用工具条颜色设置 | 根据稳定 ID 自动生成 |
| 尺寸 | 沿用半径滑块、拖动及滚轮行为 | 创建时保证可见尺寸，已有 pin 随图像视图缩放 |
| 编辑 | 操作图中形状 | 同一窗口内的右侧列表与共享编辑框 |
| 导出 | 绘入原图区域 | pin 绘入原图，同时在右侧输出说明 |

右侧是钉图窗口的一部分，不是额外的系统窗口。首次打开时可以缩小截图视图以腾出空间；这只改变显示比例。新 pin 的半径、字号和边框按创建时的 `dpi / scale` 转成原图坐标，避免大图缩小后标记变得难以看见。之后这些几何量保持在原图坐标中，后续缩放和导出都使用同一个对象。

列表可滚动，长备注显示摘要；底部的一个共享 `TextBox` 查看和编辑当前选中项的完整文字。列表不为每个批注创建输入控件。点击和拖动在图片坐标中处理，pin 中心限制在原图范围；右侧列表、编辑区及短截图下方的留白不会创建图形。收起面板不删除已有批注，也不取消导出。

编辑框拥有焦点时，输入、换行、选择、删除和文字复制由输入控件处理；`Ctrl+S` 仍可执行保存。完成放置 pin 的鼠标操作后再把焦点交给编辑框，避免鼠标捕获与输入焦点互相打断。

## 数据所有权与历史

`ShapeAnnotation` 保存 `number`、完整 `note` 和 pin 中心。`WinPin` 从活动历史收集批注，按编号排序后交给面板或导出服务；面板的列表数据是显示快照，不能取代 shape 的所有权。

窗口持有一个 `Core::AnnotationSequence`。第一个 ID 为 1，此后只增加，删除、撤销及新操作丢弃 redo 分支都不回退。因此删除 #2 后 #3 仍是 #3，新批注不会占用 #2；撤销后重做恢复的是原来的对象、文字、位置与颜色。普通序号使用自己的编号逻辑。

图形创建受现有历史栈控制。删除沿用现有的精确移除语义；备注文本原位更新，不会为每个按键创建一个新的图形历史记录。更改这套语义时需要单独设计编辑命令与历史边界，不能只调整列表序号。

`annotationColor(number)` 首先使用十种主题色，后续通过确定性的黄金角色相及饱和度/亮度变化扩展。颜色不依赖列表位置。自动前景色保证数字与徽章对比；前 256 个 ID 的 RGB 唯一性及至少 4.5:1 的文字对比度由核心测试检查。有限 RGB 色域并不意味着任意数量的标记都能在视觉上明显区分，编号始终是主要对应依据。

## 一张图片的完整导出

导出分为以下步骤：

1. `WinPin` 收集活动批注，`AnnotationRenderer::makePlan()` 为完整备注及编号创建真实 DirectWrite 布局，测量换行后的尺寸，交由 `Core::layoutAnnotations()` 选择字号和行/列位置。
2. `WinPin` 以原始图片尺寸合成底图和全部活动图形，结束离屏绘制。
3. `AnnotationRenderer::render()` 创建实际计划尺寸的 96-DPI BGRA 位图，绘制右侧备注区，再用 `CopyFromBitmap` 把已合成的原图逐像素复制到左上角。
4. 调用方按计划的实际宽高读取紧密排列的像素，再交给原有 `ImageExport` 保存 PNG 或复制到剪贴板。

合并不会缩放或重新采样左侧原图，原图部分的 alpha 也保持不变。扩高后原图下方使用白色留白。没有活动批注时不增加备注区，输出保持原图尺寸。

`makePlan()` 和 `render()` 失败时不替换调用方已有的 plan/bitmap。导出失败后调用方保留编辑内容，不能把只写出前几条备注的图片当成成功。服务不依赖 App、Ling 或全局设置，可由独立原生测试调用。

## 布局与资源限制

以下是服务默认值，最终尺寸及字体以 `Plan.layout` 为准：

| 参数 | 默认策略 |
| --- | --- |
| 一列备注宽度 | 360 个输出像素 |
| 正文字号 | 从 18px 逐步缩小，最低 12px |
| 编号字号 | 与正文适配同步，从 16px 缩小，最低 12px |
| 徽章尺寸 | 先按编号实际尺寸测量，再同步缩小，直径至少 24px |
| 行间距 | 从 16px 同步缩小，默认策略保留至少 8px |
| 标题与外侧留白 | 保持稳定，标题使用实际文字度量 |
| 短截图画布 | 尽量至少 240px 高；预算紧张时可减少不必要留白 |
| 单个位图预算 | 默认 256 MiB 的 BGRA 像素；不代表整个进程的峰值内存 |
| 最大边长 | 调用方提供实际 D2D 设备的 `GetMaximumBitmapSize()` |

每次字号变化都重新计算徽章、行距和正文可用宽度，再测量每条完整文字。这样密集的短备注也可以靠紧凑布局保留原图高度。达到最小字号仍超出时，先增加画布高度；单列超过设备或像素预算约束时，把完整的行继续排到右侧新列。

一条备注不会在列之间被拆成几个没有编号的片段。若单条备注即已超过可用边长，或全部条目无法在设备/预算中形成一张图片，返回明确失败。没有任意的条目数上限，也不会以省略号、字符串截断或隐藏末尾条目来规避限制。

中文、带换行的文字及无空格英文/URL 使用 DirectWrite 换行，关闭 trimming，并给实际 glyph overhang 留出空间。空备注使用调用方传入的本地化占位文字，因此图上的每个活动 pin 都有对应行。

## 代码扩展与验证

| 文件 | 职责 |
| --- | --- |
| `src/core/Annotation.h` | 数据结构、ID、配色、与测量实现无关的布局和尺寸/预算检查 |
| `src/editor/shapes/ShapeAnnotation.*` | pin 绘制、命中、拖动与所属备注 |
| `src/editor/WinPin.*`、`History.*` | 工具/焦点/历史协作、活动批注快照、合并导出入口 |
| `src/ui/AnnotationPanel.*` | 滚动摘要列表、选中状态、一个共享输入框 |
| `src/services/AnnotationRenderer.*` | DirectWrite 完整度量、可复用 `Plan`、Direct2D 合成 |
| `tests/annotation_tests.cpp` | 编号与历史、颜色、紧凑布局、完整行保留、溢出和预算 |
| `tests/windows/AnnotationRenderTests.cpp` | 真实字体换行、字形边界、源像素/alpha、渲染状态与 PNG |
| `tests/windows/GuiIntegrationTests.cpp` | 正式窗口、工具栏、共享输入框、历史联动与实际 PNG 剪贴板 |

纯核心回归可以在 Linux 或 Windows 使用 C++20 编译器运行。`scripts/test-windows.ps1` 在 Windows 以软件 WARP 设备编译和运行正式 renderer，输出 PNG 供检查；它覆盖空批注、中英文与空备注、多行长文、多列、无空格长 URL、紧凑短备注等场景。

`scripts/test-windows.ps1 -Gui` 另行链接已构建的正式 Release 对象，以实际窗口消息检查放置、中文字符输入、共享编辑框、列表选择、删除、撤销重做、收起后的拖动，以及从真实复制命令取得的 PNG。它有硬超时，缺少图形或输入桌面能力时明确报错，不向产品加入测试开关。

脚本输入不等于真实 IME 组合或所有物理鼠标交互，高 DPI 桌面布局、多屏和音视频也不在此覆盖内。提交时应分别记录核心测试、原生渲染、有限 GUI 自动化及桌面手工验收的真实结果，后者按 [验证清单](VALIDATION.md) 执行。
