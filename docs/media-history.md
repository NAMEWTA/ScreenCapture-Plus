# 媒体历史与剪切复制板

## 产品约定

“剪切复制板”是 huhucapture 的本地截图与录屏档案。它使用户可以在复制内容被下一次操作替换、关闭程序或重新启动后，仍找到以前的结果。它与 Windows 当前剪贴板、编辑器中的撤销历史分别管理。

入口位于截图工具条的二维码识别右侧，也可从托盘右键菜单直接打开。列表展示截图缩略图、GIF / MP4 封面与文件信息，支持再次复制、打开所在文件夹和一键清除。图片复制保留图像剪贴板格式；录屏复制稳定的媒体文件路径，方便粘贴到支持文件的应用。

历史列表采用紧凑桌面密度，预览、文字与尾部操作保持稳定的对齐。缩略图保持媒体比例，操作按钮与设置页共享字号和高度；分页控件仅在确实有多页内容时出现。显示密度与归档业务分别维护，完整视觉和命中约束见 [界面设计](design.md#媒体历史的列表密度)。

## 目录与文件名

默认目录为 Windows 系统“文档”已知文件夹下的 `huhucapture`。路径由 `FOLDERID_Documents` 解析，而非拼接固定的 `C:\Users\...\Documents`，因此能遵循用户的文档重定向，例如 OneDrive 或移动到其他磁盘的文档目录。

自动归档采用本地时间 `YYYYMMDD-HHMMSS.ext`，例如：

```text
20261124-153045.png
20261124-153046.mp4
20261124-153046-001.mp4
```

同一秒的同扩展名文件递增 `-001`、`-002` 后缀，并以排他创建避免覆盖。文件名表示保存时间，排序不依赖系统剪贴板中仍有该项。PNG、GIF 和 MP4 是本次历史管理支持的格式。

点击保存或完成复制后，结果自动归档；这包括工具条上的完成复制按钮。另存为默认打开归档目录，用户可以选择其他位置，此时仍保留归档副本。

## 保存与失败语义

截图、批注合图和长截图归档的是最终导出结果，因此历史中的图像包含当时实际保存的全部内容。归档必须使用完成导出的实际尺寸，不能重新抓屏或只保存没有批注的底图。

录屏按“停止采集 → 完成编码 → 持久化归档 → 复制稳定文件路径或另存为”的顺序结束。不能把下一次录制会覆盖的固定临时路径作为历史文件交给用户。取消另存为时，已经完成的录屏仍可从历史找回。

只有完整成功的媒体文件进入历史。归档失败明确提示；录屏的原始临时结果必须保留，截图保留编辑状态。剪贴板被其他应用占用时，也不能将未写入的内容报告为已复制。归档或另存为失败时保留能够恢复的结果，已有文件仍可通过提示中的路径定位；保存是否成功以实际写入结果为准。

## 历史的范围

历史从归档目录的顶层文件恢复，不额外引入一份必须与磁盘同步的数据库。它仅管理符合应用命名规则的 PNG / GIF / MP4，忽略子目录、其他文档与临时未完成文件。这样的范围使重启恢复简单，也约束了批量操作能影响的数据。

缩略图属于可重建的显示数据，不是媒体原件。加载使用后台有界批次；窗口关闭或条目变化后，不把旧回调写入已失效的窗口。封面不可用、文件被用户移动或删除时应提供合理占位和失败反馈，不阻塞整个历史列表。

一键清除只处理当前列表中归档的媒体，确认后默认送入系统回收站。它不递归清空用户文件夹，也不删除用户另存到其他位置的副本。Windows 无法回收时会再次提示是否永久删除；应用不静默降级为永久删除。失败或取消后保留剩余项并刷新列表。

## 扩展约束与来源

### Qt 迁移的共享归档边界

`MediaArchiveService` 沿用现有 `MediaFileName` 的时间戳、后缀与排序，直接调用
同一 `FileCommitter`。正式默认路径由 Qt `DocumentsLocation/huhucapture`
取得；目录重定向经规范化后再交平台层处理，不通过固定用户名拼接。
构造和枚举不创建目录，真正写入时才准备目标目录。该服务是同步后台 API，
UI 线程只传递完成图像、条目快照和命令，不承担扫描、解码或文件同步。

暂存令牌由服务排他创建，不能拿远端文件名冒充已有暂存。PNG 编码完成并关闭
写入者后进入完整解码与无覆盖提交；跨文件系统导入使用固定大小缓冲，读取同一
已打开普通文件，前后检查实际身份、长度和修改信息，保留源文件。符号链接、
reparse point 与 FIFO 不会被当成普通文件导入。完整 PNG 校验复用固定 Qt
`qpnghandler.cpp` 的 `png_read_image` / `png_read_end` 路径，拒绝截断和尾随内容。
GIF 和 MP4 的完整解码由实际编解码服务接入；未提供相应解码器时明确返回不支持，
不会只凭扩展名或封面允许发布。Qt GIF 的部分帧容错不能作为完整接收证据。
Qt PNG 的 `iod_read_fn` 会补造缺失的末尾 CRC；因此调用成熟解码器前另检查实际存在的完整 IEND 尾块。这个窄检查不替换 PNG 解码器，也不把 Qt 的兼容行为当作传输完整性证明。Windows 归档返回路径统一采用 Qt 分隔符，与 QDir / QFileInfo 产生的条目一致。

暂存销毁只清理本次拥有的同一文件身份。录制失败可以显式转交恢复路径；归档失败
不会销毁调用方仍持有的暂存令牌。已发布但目录同步失败的文件仍返回实际路径，
保留成品并报告持久化不确定，不重试为另一个文件，也不确认接收成功。

历史条目保存实际卷 / 文件标识、长度和修改快照。发送和预览持读租约，清理先取得
互斥移除预留；同一个文件的硬链接别名也共享忙状态。移除前必须重新核对快照，
文件被替换后不得沿用旧选择删除新对象。租约在实际传输终态后释放，窗口关闭不
释放正在使用的媒体。这里防止应用内部操作互相破坏，不宣称隔离拥有相同用户权限
的其他进程。系统回收操作和必要确认仍由平台服务承担，租约本身不删除文件。

枚举复用旧产品的受管命名范围，避免启动时全量解码所有视频；外部损坏的旧文件
可能仍有历史条目，实际读取和封面错误必须反馈。新增导入始终经过完整校验。
当前共享服务与组件的范围不能代替产品装配、真实 Documents / XDG 重定向、
回收站、系统剪贴板或两台设备的验收，状态见 [迁移边界](qt-migration.md)。
