# 工程约定

## 目录与命名

目录划分首先表达职责与依赖方向。新增代码应进入 [架构地图](architecture.md) 中已有的边界；只有现有边界确实无法承担职责时才新增目录。不要按一次需求、版本号或临时实现阶段建立平行目录。

| 类型 | 约定与理由 |
| --- | --- |
| 产品、EXE、配置根目录、发布资产 | 全小写 `huhucapture`，保证用户看到的名称、更新器和分发脚本一致 |
| C++ 命名空间 | `HuhuCapture`；纯规则放入 `Core` 等职责明确的子空间 |
| 生产 C++ 文件 | 延续所在模块的 `PascalCase.cpp/.h`；头文件路径相对 `src`，不依赖构建机绝对路径 |
| 核心行为测试 | 顶层 `tests/*.cpp` 独立入口；原生设备/窗口测试放入 `tests/windows` |
| 维护文档 | 集中 `docs/`，文件名全小写，单词用短横线；不在源码、语言或品牌资产目录重复维护说明 |
| 固定仓库入口 | 保留 `README.md`、`AGENTS.md`、`CONTRIBUTING.md`、`CHANGELOG.md`、`LICENSE` 和第三方许可原名 |
| 生成内容 | `.deps`、`artifacts`、IDE 状态、测试缓存和个人配置均不提交 |

新增生产源文件必须同时登记到 Windows 工程和 filters。把文件放进目录本身不会使 MSBuild 编译它。变更依赖时修改锁文件和许可清单，不以修改恢复目录中的源码代替可复现升级。

## 代码与所有权

优先复用现有能力和 Windows 系统组件。保持原生单 EXE，不为局部交互引入新的运行时、服务进程或插件框架。外部项目可以帮助确认产品行为；复制代码前必须核对许可及依赖成本。

每个句柄、COM 对象、像素缓冲与工作线程都必须能回答：谁创建、谁拥有、何时借用、何时失效、由哪个线程释放。使用 RAII；异步回调使用明确的生命周期令牌，不能仅捕获裸 `this` 后假定窗口仍存在。先停止并 join 工作线程，再释放它可能访问的资源。

配置、语言和窗口对象归 UI 线程。后台媒体工作使用已复制的数据；回到 UI 线程时再次核对窗口生命周期。捕获鼠标的对象不能被无关布局或语言弹层销毁；被动布局不得抢走焦点。

像素边界写清 BGRA/RGB、stride、上下方向、alpha 和借用寿命。宽高乘法、内存预算和设备边长在分配前校验。导出读取实际合成尺寸；不能使用原图尺寸读取加了说明栏的位图。

## 失败与数据保护

保存成功是文件完整落盘后的事实。归档失败、剪贴板被占用、编码失败和取消另存为应分别处理；不能用“已复制”掩盖写入失败，也不能在失败后销毁唯一的编辑结果或录屏文件。自动归档使用排他创建避免重名覆盖；临时文件成功提交后才进入历史。

批量清理以应用管理的媒体范围为界。不得通过递归清空用户选择的整个文件夹来实现“清空历史”；取消与失败必须保留尚未处理的项目。历史记录、编辑器撤销历史和 Windows 系统剪贴板是三个不同的生命周期，扩展时不要混用。

对用户有可见影响的默认值、快捷键、帧率、编码选择、编号和文件命名均属于产品契约。内部重构保持这些行为；需求要求改变时，同步操作说明、失败语义和必要的验证。

## UI 与可访问性

设置页和媒体历史遵循 [界面设计](design.md)，品牌插画遵循 [品牌资源](brand.md)。功能颜色与插画颜色各有职责。正文与辅助文字保持可读的字号和对比度；控件具有明确的悬停、选中、禁用和焦点反馈。

交互尺寸以逻辑像素定义并随 DPI 缩放。校验窄窗口、长译文和高 DPI 的内容滚动与命中；文字缩小到难以阅读不能作为解决溢出的方式。图标按钮保留本地化提示，清空历史应明确说明影响范围。

## 文档与提交

文档应说明“为什么这样设计”“哪些约束不能破坏”“失败时用户数据怎么办”“怎样验证边界”。目录职责、跨模块契约、取舍与不可见的生命周期值得记录；函数签名、字段清单和常量值直接链接源码即可。相同规则指定一个主要来源，其他文档链接引用。

修改涉及的链接全部使用精确大小写。版本说明描述变化，不把计划中的检查写成已经通过的结果。提交说明包含具体问题、改后的行为和真实验证结果；无法在当前环境执行的检查直接列明。
