# 验证与功能保持

## 自动化覆盖

`pwsh scripts/test.ps1` 对 `tests/*.cpp` 分别编译并执行，不依赖测试框架、显示器或用户账号。检查使用失败退出码，不会因 Release 定义 `NDEBUG` 而被跳过。

| 测试 | 主要风险 |
| --- | --- |
| `PixelBufferTests.cpp` | 尺寸乘法溢出、缓冲长度、奇数宽、多行、BGRA→RGB 通道顺序、alpha 规范化、越界哨兵 |
| `history_tests.cpp` | 空历史、删除非首项、撤销边界、清 redo、借用解除、延迟回调、地址复用、10,000 条记录扩容 |
| `scroll_stitch_tests.cpp` | 1,200 次与原始匹配公式对比、100 次拼接像素对比、空白条带与 tie-breaking、灰度权重、非法输入不改结果 |
| `release_version_tests.cpp` | 三段标签、可选 v、WORD 上限、非法/预发布标签拒绝、数值版本顺序 |

`scripts/smoke.ps1` 把 EXE 复制到隔离临时目录，仅放一个空 `config.json`，以 `--enter=tray` 启动，确认三秒内没有提前退出，然后只结束它自己创建的进程并清理临时目录。此检查验证基本启动、便携配置和内置语言资源，不声称验证了截图、显卡、声音或全部 GUI。

`scripts/package.ps1` 检查 EXE 版本和 PE 依赖，再生成可校验资产。GitHub Actions 同时验证 x64 Release 与 Debug；正式 Release 只发布 Release 产物。

纯 C++ 核心也可以在 Linux/macOS 用 C++20 编译器运行，例如：

```bash
g++ -std=c++20 -O2 -Wall -Wextra -Werror -pedantic -Isrc tests/scroll_stitch_tests.cpp -o /tmp/scroll_stitch_tests
/tmp/scroll_stitch_tests
```

## Windows 桌面验收矩阵

以下是人工发布验收清单，不代表已经自动执行通过。应在实际 Windows 桌面、至少一个双屏/混合 DPI 环境完成，并记录系统、显卡、驱动与音源配置。

| 场景 | 操作与预期 |
| --- | --- |
| 启动/常驻 | 默认启动截图；`--enter=tray` 只驻托盘；第二次启动/全局热键唤起截图；退出无残留线程 |
| 框选 | 单屏、负坐标副屏、跨屏选区、调整八个方向、Esc 取消、取色复制 RGB/HEX/CMYK |
| 标注 | 八种工具逐一新建、拖动、改样式、删除；Shift 圆/方/直线；删除中间图形不影响首项 |
| 历史 | 连续撤销/重做；撤销后新画清 redo；文本为空时切换工具；排队删除后立即关窗 |
| 文本/输入法 | 中文输入、光标选择、编辑中 Ctrl+Z、点击工具条切工具、样式实时更新 |
| 钉图 | 多窗口、移动、Ctrl+滚轮缩放、原尺寸导出、双击完成、关闭窗口 |
| 图像导出 | PNG 打开正确；复制到浏览器/Electron/Office/旧式 DIB 消费端；取消保存不丢图 |
| 长截图 | 浏览器平滑滚动、固定顶部、纯色顶部、底部兜底、滚到底、非常窄的选区、连续多段、停止后保存/钉图 |
| GIF | 奇数宽、指针显示、录制后停止、刚开始立即停止、中文路径、长时间录制、重复开始/结束 |
| MP4 | 单屏、副屏、混合显卡、HEVC 不可用回退 H.264、仅扬声器/仅麦克风/两者/无音源 |
| 录屏退出 | 录制中退出程序、静音或拔出音频设备后停止、设备无数据时停止；确认文件可播放、无后台线程 |
| OCR/QR | OCR 放 EXE 旁和 plugin 目录两种位置；缺插件时打开原下载页；中文/镜像/多二维码 |
| 语言/配置 | 空 config、缺少 shortcutKey、第三方语言缺 key/格式错误、切回中英文；未知配置字段保留 |
| 自动更新 | 已有稳定 Release、尚无资产、取消更新、目录不可写、请求中退出；最终只安装同 Release 的 EXE |
| 命令行 | `--enter=pin/long/video/ocr/qr/tray`，配合 `--auto-quit=true`；未知 enter 保持默认工具条 |

## 性能测量方法

使用相同 Windows 系统、相同电源/显卡模式、相同区域大小、内容、帧率和音源，对基线提交与候选提交各执行至少三次。记录中位数及异常，不用一次截图推断性能。

1. 启动到可框选：记录时间、初始私有内存、GDI/USER 句柄数。
2. 4K GIF：录制同一段 60 秒场景，记录 CPU、私有内存峰值、帧数/实际时长、文件大小。区分捕获与 gifski 编码成本。
3. 长图：记录每步耗时、累计结果尺寸和峰值内存；验证最终像素及窄选区预览。
4. 标注：建立 1,000 个图形，撤销大部分后检查拖动/悬停；单独记录渲染成本与历史游标成本。
5. MP4：分别录制整屏和小选区；检查停止延迟、音视频同步及无音频包时 CPU。
6. 循环 50 次截图/关闭和 20 次录屏/停止：检查句柄及线程是否持续增长。

代码中的帧拷贝减少和算法复杂度改善可以从实现确认；端到端 CPU/帧率提升必须由以上实测支持。暂未测量的指标保持空缺，不填写推测百分比。
