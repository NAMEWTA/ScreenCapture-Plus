### Windows 原生备注导出

`pwsh scripts/test-windows.ps1` 构建独立的 `AnnotationRenderTests.exe`，编译应用实际使用的 `src/services/AnnotationRenderer.cpp`。测试通过 D3D11 WARP 创建软件设备，使用真实 Direct2D/DirectWrite 绘制，再用 WIC 编码 PNG 并重新解码。

检查内容包括：完整保留备注文本与稳定编号/颜色；真实换行和字形外伸不超出备注区域；紧凑编号仍适配徽标；无备注时不增加画布；有备注时原图位于左侧且像素逐字节不变；半透明 BGRA 不被白底混合；输出以 96 DPI 像素坐标工作；调用后恢复原渲染目标、DPI、变换、单位、抗锯齿与混合模式。无效输入及超尺寸/内存预算应整体失败。

| PNG | 场景与检查 |
| --- | --- |
| `01-no-annotations.png` | 无备注，导出宽高与所有源像素保持不变 |
| `02-cjk-and-empty-note.png` | 中文、英文、空备注占位文本；保留不连续编号与对应颜色 |
| `03-long-multiline-notes.png` | 长备注与显式换行；扩展画布容纳全文，无省略号裁切 |
| `04-many-notes-multiple-columns.png` | 45 条备注在受限最大尺寸下完整流入多列，每条都可见 |
| `05-unbroken-url.png` | 很长且没有空格的 URL；真实 DirectWrite 行数大于 1，字宽与字形边界不越界 |
| `06-compact-short-notes.png` | 5 条短备注收缩正文、编号及间距，仍容纳在原图 280 像素高度内 |

所有 PNG 都再次解码，核对尺寸及不透明像素与合成缓冲一致。文件、测试 EXE/PDB 和报告位于 `artifacts/tests/windows/`，CI 上传为 `windows-render-checks`，失败时也保留已生成的诊断结果。

这些 PNG 的左侧是明确标记的合成测试图，右侧由生产备注导出器渲染；它们是原生导出集成证据，不代表已经自动点击并验证了完整桌面编辑器。图形鼠标命中、中文输入法、窗口焦点和多显示器交互仍需下述桌面验收。

### 真实 Windows 编辑器交互

`pwsh scripts/test-windows.ps1 -Gui` 链接正式 Release 的对象文件、资源及依赖，由独立入口启动真实应用和 `WinPin`。它使用隔离配置，通过真实 HWND 的鼠标消息、同步光标/按键状态及 `WM_CHAR` 输入驱动控件；不复制一份编辑器实现，也不增加产品测试开关。

目标检查包括：

- 点击真实工具条选择批注，正向和反向拖出不同颜色的矩形，检查较小的编号位于左上角；松手后直接输入中文/英文备注，确认焦点正确、没有串写。
- 点击列表切换编辑项，修改第一条后保持第二条不变；通过删除区删除选中标记，再通过工具条执行撤销/重做并检查对应备注。
- 编辑框拥有焦点后再次拖动图片，创建新区域且不复用已删除编号；单击、零宽/零高和 1px 误拖不留下空批注。
- 拖动右下角调整大小，拖动编号移动完整范围；越过四条图像边界时保持尺寸并限制在原图内。
- 中途释放鼠标捕获后，未完成的新区域删除，已有区域保留最后有效位置；鼠标返回时不继续拖动，并能继续正常操作。
- 选择另一个画图工具、折叠备注栏、把窗口移动到显示器边缘，再拖动已有标记；备注栏重新展开时不产生位置跳变。无工具选中时仍按产品原有语义拖动窗口。
- 保存真实桌面画面，执行实际工具条“复制”动作，从系统剪贴板取出 PNG 并解码，检查合并图包含原图和右侧备注，矩形边框/编号/右侧徽章颜色一致，区域内部没有被填色。

证据保存在 `artifacts/tests/windows/gui/`：`test-report.txt`、测试程序，以及 `screens/01-editor-two-notes.png`、`screens/02-editor-after-drag.png`、`screens/03-real-editor-clipboard.png`。它们随同 `windows-render-checks` 上传，与前述合成测试图分开保存。

GUI 进程有 45 秒硬超时，只结束测试启动的进程。启动前探测硬件 D3D11 与输入桌面；能力不可用返回独立的 77 错误码，CI 明确失败。普通 EXE、核心测试、WARP 和打包步骤位于此检查之前，其结果仍可查看，声明版本发布不会把未通过的 GUI 检查当成成功。

这组测试覆盖受控窗口上的关键编辑路径。`WM_CHAR` 输入不能替代真实中文输入法组词、系统候选窗、高 DPI 多显示器、硬件录屏与音频验收；这些仍需记录下表中的桌面实测结果。

### 启动与打包

`scripts/smoke.ps1` 将 Release EXE 复制到隔离临时目录，只放空 `config.json`，以 `--enter=tray` 启动。确认三秒内没有提前退出后，只结束测试创建的进程并清理目录。它检查基本启动、便携配置与内置语言资源，不把显卡、声音或完整 GUI 行为算作已验证。

`scripts/package.ps1` 检查 EXE 版本与 PE 依赖，生成可校验资产。PR 与 main push 同时验证 x64 Release/Debug；发布只上传 Release EXE。声明版本发布 job 另核对 `releases/publish.json`、本次 SHA、版本、资产全集与 SHA256，原子创建新标签后上传发布；已发布版本保持原样。

## 性能测量方法

使用相同 Windows 系统、电源/显卡模式、区域尺寸、内容、帧率和音源，对基线和候选版本各执行至少三次。记录中位数及异常，不用一张测试 PNG 推断端到端性能。

1. 启动到可框选：时间、初始私有内存、GDI/USER 句柄。
2. 标注：分别创建 1、10、50 条备注，包含短文本、中文长文和长 URL；记录输入/滚动/拖动响应、布局时间、导出尺寸、峰值内存；关注文字修改后的重排，不只测静态画面。
3. 4K GIF：同一段 60 秒场景的 CPU、内存、帧数/时长、文件大小；区分捕获和 gifski 编码成本。
4. 长图：每次拼接耗时、累计尺寸与峰值内存，核对最终像素和窄选区预览。
5. 图形历史：1,000 个图形及大量撤销后的拖动/悬停；区分渲染与历史遍历成本。
6. MP4：整屏与小选区、停止延迟、音视频同步、无音频包时 CPU。
7. 循环 50 次截图/关闭、20 次录屏/停止，检查句柄与线程是否持续增长。

没有实际测量的数据保持空缺，不填写推测的性能百分比。原生渲染测试主要证明导出正确性与边界处理，不替代硬件和桌面性能测量。
