# 编辑输出与历史的应用所有权

`src/app/MediaWorkspace` 把同一 Qt 编辑器、历史窗口、归档和桌面系统服务连接为实际操作链路。它由应用拥有，接收唯一 `MediaArchiveService`、`SystemClipboard` 和 `FileRevealer`；没有另一套归档目录、平台窗口或媒体业务实现。视频首帧读取器由应用连接已有 `videoThumbnail`，缺少读取器时返回明确不支持，不能拿图片占位冒充解码。

这一层已经登记到双平台 Qt 验证目标，实际构建结果以对应提交的 CI 为准，尚不是完整 `QApplication` 产品入口。采集会话、托盘、全局快捷键、录制和局域网控制层仍须在正式宿主装配后完成各自验收。

## 编辑输出

共享编辑器先在 GUI 线程结束输入法组合并合成完整批注图像，再把不可变图像快照交给应用。应用的两个 worker 和最多八个已接纳操作执行编码、读取及文件操作；等待处理的输入图像合计限为 512 MiB。超出预算时保留文档并报告繁忙，不建立无限队列。

截图会话通过同一个 `outputImage` 入口提交已经裁剪的图像、请求所有者和令牌；不为复制或另存创建隐藏编辑器。编辑器也调用这一入口。请求从对话框、目标检查到提交始终由同一个输出目标拥有，等待选择或覆盖确认的图像同样计入八个请求和 512 MiB 预算。所有者销毁会取消请求并禁止晚到完成回调。

复制延续原产品的顺序：先成功归档，再准备 PNG / 原生格式，最后在 GUI 线程请求真实剪贴板发布。只有对应桌面服务确认成功，编辑器才收到成功结果。剪贴板拒绝、失去 Wayland 焦点或取消都保留已经归档的文件；原编辑文档也保留。普通捕获编辑器成功后可关闭，贴图编辑器继续显示。

另存使用 Qt 的实际保存对话框。选定路径后先在 worker 中记录目标文件身份，再对确实存在的文件显示一次覆盖确认。这个确认绑定该文件快照；目标原本不存在时，排队期间新出现的同名文件也不获得覆盖许可。取消选择不产生新归档。确认后先完成统一归档，再以 64 KiB 缓冲复制归档原始字节。这一顺序比旧保存入口更明确地保护第二个写入失败时的已完成媒体：外部目标写入失败仍保留归档，并把其路径交回编辑器显示。最终复制不重新编码，因此两个文件的内容一致。目标目录必须已存在；不创建用户未选定的目录。

源文件在复制期间持有精确身份的共享读取 lease，读前、读后核对实际打开的文件及名称快照。目标不跟随最终路径的符号链接或重解析点。目标是已有受管历史文件时，还须获得同一归档的独占移除 reservation；正在发送或读取的文件不能被另存覆盖。写入前后核对确认时的目标快照，遇到外部变化保留原目标。不存在的目标复用 `FileCommitter` 的独占暂存和无覆盖发布，最后一刻出现同名文件也不会覆盖。已经明确确认的已有目标使用 `QSaveFile` 原子替换；快照检查与替换不是针对不合作进程的原子比较交换，应用内写入仍由统一 lease 协调。`QSaveFile` 的替换不能宣称获得 `FileCommitter` 的文件与目录同步保证。

## 历史、封面与清理

历史窗口只持当前显示快照。列表、PNG 完整解码、首帧封面和复制准备在 worker 中执行；GUI 只接收有代号的完成结果和 `QImage`，不在 worker 创建 `QPixmap` 或控件。切换页面取消前一页仍未结束的封面任务，晚到结果还要通过窗口的 generation 检查。

封面缓存最多保留 64 MiB 的解码图像，键包括实际文件身份、大小、修改快照、媒体类型和所需尺寸。读取命中也必须核对当前文件，不能在用户替换同名文件后返回旧图。缓存不持媒体 lease，原文件可以在窗口关闭后照常清理。PNG 使用已有完整 libpng 检查，GIF 和 MP4 封面仅是预览，不能用来授权接收归档或发送。

PNG 预览进入同一个贴图编辑器；GIF / MP4 使用 Qt 桌面 URL 服务请求系统关联程序打开。这里的成功只表示系统接受启动请求，不声称播放器已经解码、播放或安装相应编码器。

清理只处理历史 UI 已明确确认的精确条目，顺序调用真实回收服务。不能回收且原身份仍有效的条目，才持有服务生成的 `PermanentRemovalPermit` 并显示第二次确认。永久删除只消费这组精确许可；关闭窗口或拒绝确认就放弃许可，不能自动降级为删除。遇到繁忙、文件变化或失败，刷新剩余历史并保留具体错误。

## 生命周期与验证边界

关闭历史或编辑窗口会取消它尚未完成的界面工作；已发布归档不会回滚。发送另由 `LanController` 和同一 `TransferService` 持有，历史窗口关闭不会取消传输。应用退出先停止新请求、发出 stop，再等待自己的 worker 结束，最后销毁窗口和服务。

取消同样覆盖 worker 已完成、GUI 完成通知仍在队列中的间隙；这种完成不能再发起归档、覆盖确认、剪贴板或文件管理器操作。保存和覆盖确认框也登记为该编辑器请求的一部分，关闭编辑器会拒绝对应问题，没有 worker 时也不会遗失取消。已经完成的持久归档仍通过实际结果刷新历史。

`qt_media_workspace` 使用真实文件系统、共享 Qt 窗口、实际保存对话框控件和系统剪贴板服务。它检查像素和文件字节、受管目标繁忙保护、外部修改后的封面失效、取消保存、销毁编辑窗口以及重新打开历史。在 Linux 离屏环境中，剪贴板失败被作为真实的拒绝路径检查；独立 X11 / Wayland / Windows 剪贴板验证仍由桌面服务测试承担。Qt 对话框测试不等于原生系统文件选择器、物理输入、中文 IME 或混合 DPI 验收。
