# 共享局域网界面与应用装配

本页说明 [Issue #5](https://github.com/NAMEWTA/huhucapture/issues/5) P10 的
Qt 展示边界，不改变 [TransferService](transfer-service.md) 或
[固定 Rust core](rust-bridge.md) 的协议、校验与归档职责。

## 唯一服务与窗口寿命

`TransferWindow`、`ReceivePrompt`、`TransferSettingsPanel` 均借用同一个
应用级 `TransferService`。界面不拥有 Rust runtime、接收正文或归档 worker。
进度及完成结果来自真实服务的 `Event`、`receiveProgress` 和 `receivedFiles`；
字节达到总量只显示等待验证和保存，成功只能来自真实完成结果。

关闭任务窗或设置窗只解除订阅；重开从服务只读快照恢复。关闭尚未回答的接收
确认窗则明确拒绝该请求。若命令队列暂时满而无法提交拒绝，确认窗保留并显示
实际错误；不能消失后谎称拒绝已交付。退出应用由宿主停止服务并完成 worker
回收，不依赖窗口析构完成网络关闭。

历史页的发送入口使用 Qt 标准图标，固定为 32×32 DIP，并保留完整的工具提示、
无障碍名称与右键发送菜单。菜单保存用户点击条目的精确身份，列表刷新后不会
把同一行号误用成另一个文件。设置页只有在宿主提供真实能力后显示局域网入口；
详细网络设置放在独立的共享面板中。

## 发送确认与后台准备

设备列表中的 alias 仅供显示。可发送的设备必须具有实际 TLS 探测得到的证书
指纹；未验证的发现条目需要执行“重新验证所选设备”。手动地址只接受具体 IPv4
和有效端口，实际探测仍走原服务。刷新保留所选端点，多端点按证书合并为一个
设备条目，不按显示名选择身份。同一端点有冲突指纹时必须实际重新探测。

`peerReviewRequested` 要求宿主从已加载的信任配置返回该端点的已保存指纹。
没有记录和证书变化是两个独立的确认状态；证书变化时同时展示旧、新指纹。
存储读取失败不允许发送，亦不会随每个进度刷新无限重试读取。确认框默认“不”。
显示协议错误时只使用结构化状态和 HTTP 码，不通过匹配英文错误文案猜测原因。

用户确认后，`prepareSendRequested` 将精确媒体条目、已确认的原生 peer JSON
及独立显示名移交应用宿主。宿主必须持有此意图，在线程池中执行
`validatedLease` / `PreparedMedia::open`，然后在应用线程调用同一个
`TransferService::send`。**这条完成回调的存活上下文必须是应用服务，而不是
窗口。** 即使用户关闭、销毁窗口，已确认的准备与发送也继续。界面仍存在时，
用真实 `Submission` 完成 `completePreparation`；不能用命令入队替代发送完成。

界面不持媒体 lease。服务保存到真实发送终态的原生句柄与历史读租约仍是唯一
发送拥有者；只读活动快照保存路径、完整整数文件身份、长度及媒体类型。
重试重新探测设备，并要求宿主对这些原始条目重新取得和校验租约。部分成功时
仅重试未成功的条目，不自动再次发送已经确认保存的文件。PIN 只存在于一次
已确认意图和协议调用中，不进入活动快照。

## 有界只读快照

服务复用 `Event` 建立读模型：每个发送保留最初的 `SendQueued` 和最新进度，
每个接收保留原始 offer、明确决策、按文件合并的最新写入进度及最终结果。
这些值没有额外任务控制权。未知或过期会话的失败 accept 命令不会制造一个永不
结束的活动记录。

预算在 `TransferLimits` 集中定义：每次发送的源描述最多 128 KiB；已完成传输
最多 16 项、8 MiB；最近探测另有 16 项、256 KiB，不能靠反复刷新挤掉传输结果。
已完成记录最多保留 30 分钟；活动记录随原服务的有界命令和终态预留存在。
设备列表只保留一个最新快照。预算统计的是受控事件与字符串大小，不是已经完成
实际 RSS 测量的结论。长期媒体记录仍由真实归档目录承担。

事件带有服务发布顺序。重新打开窗口时，旧的手动探测不能覆盖更新的设备快照，
包括已移除的设备或已变化的证书。接收终态中的每个已发布路径原样提供给定位
操作；即使持久化失败或晚到取消，也不会隐去已经生成的实际文件。

## 配置职责与验证范围

`TransferSettingsPanel` 显示宿主提供的实际网卡、具体地址、可用性、已保存选择、
端口及本机指纹。虚拟网络标记由宿主提供，不按网卡名称猜测。新网络或 VPN
不会自动加入允许范围，已经消失的已选接口会显示为不可用。应用设置时，由
宿主完成持久 TLS 身份、网卡策略、配置保存及必要的受控停止/重启；任何失败
都返回实际生效快照，窗口不能提前宣布启用。

`qt_transfer_ui` 使用真实 Qt 控件、官方 TLS 身份、两个真实 loopback 端点和
生产 `ReceiveArchiveSink`。测试覆盖真实 PNG 归档、窗口销毁后继续已确认发送、
拒绝对应的 HTTP 403、部分接受及重新准备、实际换证书、只读快照不持 lease、
有界近期记录和六份实际语言资源，并输出实际窗口 PNG。必须以执行该目标的
CI 结果和图像检查为准，测试源码存在本身不表示通过。

应用拥有的 [LanController](lan-controller.md) 负责身份/信任持久化、网卡设置、
全局接收提示、共享归档及独立于窗口的发送准备。`DiscoveryHandle::announce`
已通过同一个有界服务提供公告刷新，不自动扫描子网。完整 QApplication 最终
装配、多网卡和防火墙、物理双端及全媒体互传仍需要独立验收。
现有协议错误类别也不能完整区分连接故障和 TLS 身份故障。没有这些真实证据时，
不得把组件窗口、loopback 或六语 PNG 当作 P10a/P12 的完整产品验收。
