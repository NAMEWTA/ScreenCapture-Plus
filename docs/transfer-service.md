# 共享局域网应用服务

本服务遵循 Issue #5 的 P10 和 Issue #4 的传输合同，协议与 TLS 仍由固定
[LocalSend core / Rust ABI](rust-bridge.md) 实现。`TransferService` 是 Qt 应用级
服务；设置页、历史页和设备页仅订阅状态、提交用户命令。关闭窗口不停止任务。
当前组件和服务验证不能替代两台真实设备、网卡与桌面的验收。

## 线程与有界通知

GUI facade 把小型值命令交给唯一 actor；后者拥有创建、发现、控制、轮询和停止
Rust 引擎的调用。通知有项数、字节和终态预留预算，GUI 以 100 ms 周期批量取值。
发送和接收的字节进度合并为最新快照；确认、失败和终态不能被进度挤掉。
没有逐块排入 Qt 事件循环的文件数据，也不要求 GUI 回调才能回收 worker。

同一 facade 保留有界只读活动快照，供 [共享局域网界面](lan-interface.md) 重开时
恢复设备、确认、进度和真实终态。`SendQueued` 只表示本地命令 admission；它的
源描述没有媒体 lease。`ReceiveDecisionQueued` 也不表示空间检查或接收已经
成功。终态记录和定点探测采用不同的有限预算，刷新设备不会挤掉传输结果。

`refreshDiscovery` 与发送/定点发现复用原 actor 和 operation 预算，只调用官方
公告。`DiscoveryRefreshed` 报告该次公告的真实完成或失败，不表示所有邻居已
响应，也不额外保留无意义的长期任务记录。

`ReceiveArchiveSink` 使用两个 worker、最多八个等待文件和十六个已预留结果槽。
默认同时接受两个会话，每会话最多 64 个文件，单文件最多 32 GiB。这些是应用
资源政策，不扩大协议支持范围；首发仍以单个已归档媒体的用户旅程为门槛。

每个成功移交的 receive 都有独立 attempt 和一个预留结果槽。结果在释放该
receive 后发布，包含实际归档路径、是否已发布和状态。旧失败尝试不能覆盖新的
重试结果。native 会话终态可以先到；actor 等待全部已接纳 attempt 的本地结果，
再给界面一个完整会话终态。关闭时先取消并 join 接收 worker，再停止、排空并
释放 Rust 引擎。结果发布不等待消费者腾出空间，避免 join 与满队列互相等待。

## 接受、写入和成功边界

用户接受前，sink 校验所选元数据、声明总量、其他任务尚未写入的预留字节、
实际归档文件系统的可用空间和默认 64 MiB 余量，并实际创建一个自有排他文件
确认目标可写。检查失败不接受正文。策略预算、存储错误和用户拒绝分别通过
标准 HTTP 413、507 和 403 返回；发送方不会把空间不足显示成对方主动拒绝。
磁盘预留属于本应用的并发记账，不能阻止其他进程占用空间，实际写入仍检查错误。

写入顺序是：打开并确认同一个自有空暂存文件 → 有界读取和写入 → 精确 EOF
长度与 SHA / 类型验证 → 关闭 writer → 完整媒体解码 → 发布前取消检查 →
共享归档服务的无覆盖持久提交 → HTTP 成功。累计长度在首个越界块落盘前拒绝。
接收进度记录实际无用户态缓冲的写入字节；100% 字节不代表完整解码或落盘成功。

临时文件的 token 和实际 writer 身份来自同一个 `StagingFile::openWriter`。
它不先截断路径，不跟随链接，确认普通文件身份与空长度后才交付写句柄。路径
被替换或打开后改名时，已有句柄不会把字节写进替换文件。媒体写入者显式关闭
并检查关闭结果，最后才调用 [共享归档服务](media-history.md)。

失败、取消或解码不支持不会得到成功 ACK。已发布但持久化未知，以及发布后
取消或成功回执丢失，均保留真实最终路径。已经发布的会话文件在唤醒 HTTP
完成前就建立禁止重放的状态，防止同 token 的立即重试产生第二份归档。
另一个会话中用户主动再发送仍是新的操作，不擅自进行跨会话去重。

## 发送与历史文件

发送准备在 worker 上调用 `MediaArchiveService::validatedLease`，完整检查
所选媒体并重验身份，再用 `PreparedMedia::open` 打开原生稳定文件句柄。
C ABI 返回实际打开对象的完整整数身份和长度；它们必须与历史租约一致。
历史租约和原生句柄保留到真实发送终态，清理会跳过同一文件及其硬链接别名。
文件名、缩略图或一次打开成功本身都不是完整媒体的证明。

Linux 同一用户的其他进程仍可能原地改写文件；租约不被描述为文件系统沙箱。
长度、哈希、类型与接收端完整解码共同决定传输结果，失败不能变成空文件成功。

## 验证边界

`qt_transfer_service` 使用生产 sink、真实临时文件、官方身份和 loopback TLS，
覆盖 PNG / GIF、拒绝与预算、取消、通知背压、源租约、重复启用和不处理 GUI
事件时的最终释放。取消测试的调度栅栏仅控制完整 codec 调用前的时机，之后仍
调用实际 GIF 解码器；它不声称已经命中特定 LZW 指令中的中断。

这些新增用例须以对应提交的 CI 结果为准，不能因测试源码存在就标成通过。
应用装配和持久身份见 [LanController](lan-controller.md)。MP4 端到端互传、
完整产品装配、双平台双向实体互传、多网卡 / 组播、
实际性能与长时稳定性仍是未解除的产品发布门槛。
