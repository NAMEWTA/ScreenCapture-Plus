# 界面设计约定

## 桌面工具的比例

设置页和媒体历史采用紧凑的桌面布局：清晰的字号层级、稳定的对齐线、适量留白，以及与触发控件一致的弹层。沿用用户指定的 [Apple 设计分析](https://github.com/VoltAgent/awesome-design-md/blob/main/design-md/apple/DESIGN.md) 中的中性色、分组和单一交互蓝，并按 Windows 桌面阅读距离与输入方式确定密度。

Apple 的 [Typography](https://developer.apple.com/design/human-interface-guidelines/typography) 分别给出 macOS 与 iOS 的默认字号；这说明平台与场景决定密度，不能把移动端字号和触控尺寸直接套到所有桌面设置。Windows 使用系统字体，由 DirectWrite 提供中文等字形回退；不随程序分发 Apple 专有字体。

### 参考来源与采用范围

| 参考 | 在本项目中采用的规则 |
| --- | --- |
| [Apple Layout](https://developer.apple.com/design/human-interface-guidelines/layout) | 用共同对齐线关联标签和操作，以分组表达相关设置，并适应窗口和字体变化 |
| [Fluent 2 Typography](https://fluent2.microsoft.design/typography) | 桌面正文与辅助文字形成稳定层级，控制字重数量，默认左对齐 |
| [Windows Typography](https://learn.microsoft.com/en-us/windows/apps/design/signature-experiences/typography) | 以逻辑像素设计，保持系统 DPI 缩放与清晰字形，不按屏幕物理像素硬缩小文字 |
| [WinUI Gallery 设置页](https://github.com/microsoft/WinUI-Gallery/blob/main/WinUIGallery/Pages/SettingsPage.xaml) | 限制内容列宽度、统一分组与行内控件；参考组织方式，不照搬完整 Gallery 页面的宽度 |
| [Windows ComboBox](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/combo-box) 与 [Gallery 示例](https://github.com/microsoft/WinUI-Gallery/blob/main/WinUIGallery/Samples/ComboBox/ComboBoxPage.xaml) | 明确当前选择；箭头导航与提交分离，点击或 Enter 提交，取消不改值 |

这些参考定义视觉与交互意图。Qt 迁移采用同一套 Widgets 控件、布局和业务状态，两端共用字号、间距与交互规则。旧 Windows 产品的 Ling / DirectWrite 实现作为 P12 之前的行为基线；迁移状态见 [Qt 跨平台迁移](qt-migration.md)。

## 内容如何居中与对齐

设置窗口默认以 **720 × 500 逻辑像素**组织，侧栏宽 **160**。窗口先受当前工作区约束，再居中显示。右侧使用最大宽度 **560** 的内容列，至少保留 **24** 的左右边距；窗口加宽时由两侧空白吸收空间，避免设置名称与操作按钮越拉越远。

“居中”分为不同层次：

- 内容列在可用区域内水平居中，三个页面共用同一条标题与卡片起始线。
- 一行中的开关、下拉框和文字组垂直居中；双行说明作为整体参与对齐。
- 标签、说明、路径和下拉选项按阅读顺序左对齐，短按钮文案居中。

不要把全部段落改为居中文字，也不要为了填满窗口而增加空白行或放大所有控件。页面切换保持标题位置稳定；可用高度降低时优先调整留白和非必要说明，主要操作不能被挤出可见区域。

## 设置页的视觉层级

以下数值定义桌面设置的比例关系，统一由设置主题维护。界面在 125% DPI 下按同一比例渲染，不额外放大一遍；例如默认窗口约为 900 × 625 物理像素，仍需接受工作区限制。

| 职责 | 约定 |
| --- | --- |
| 页面标题 | 22 / 30 逻辑像素，半粗体 |
| 正文、导航、按钮和下拉选项 | 14 / 20，常规字重；少量需要强调的名称用半粗体 |
| 辅助说明与路径 | 12 / 18，使用可读的次要文字色 |
| 设置控件 | 高 32，文本与图标垂直居中 |
| 设置行 | 单行高 48；含说明的双行高 56 |
| 卡片与按钮 | 卡片圆角 12，按钮圆角 8；卡片左右内边距 18，内容组间距 16 |
| 画布与内容 | 浅灰 `#f5f5f7`、白色 `#ffffff`，用轻边界与间距区分层次 |
| 文字 | 主文字 `#1d1d1f`，辅助文字 `#636366` |
| 交互 | `#0066cc` 为主要蓝色，焦点边界保持清晰，选中与悬停状态可区分 |

字号、行高、控件高度和间距应一起评估。只增大字体会挤压内容，只缩小字体会损失可读性。截图工具条和媒体历史有各自的操作密度；不能通过修改全局常量，把设置页的紧凑尺寸传播到捕获工具条的 44px 点击区域。

Qt 的结构性滚动容器需要同时保持 viewport 和内容背景透明。
固定 Qt 的 [`QScrollArea::setWidget`](https://github.com/qt/qtbase/blob/5af1a37e31a869cd6eb8a73d82e2c71a450e6634/src/widgets/widgets/qscrollarea.cpp)
会主动打开内容控件的 `autoFillBackground`，因此应在交给滚动容器之后再关闭它。
设置页、历史行容器和批注页脚沿用各自已有画布；白色卡片与文本输入仍自行绘制。
只给 `QScrollArea` 设置透明样式不足以消除内容上的系统默认灰色矩形。

虎虎图标和品牌插画保留自身的橘色与奶油色，规则见 [品牌资源](brand.md)。品牌插画与自动批注配色不决定设置页的背景和选中颜色。

## 媒体历史的列表密度

历史窗口的主要内容是用户保存的图像与录屏。每行以缩略图、文件名和时间/大小信息为主体，复制和定位操作放在稳定的尾部位置，并与行内容垂直居中。行内操作采用中性色轻按钮；蓝色用于选择、焦点与必要的状态，避免每一行都出现抢夺注意力的大色块。

列表与设置页共用正文、辅助文字和常规控件的比例，普通按钮高 32 逻辑像素。缩略图按原始宽高比居中适配，保留边缘留白，不为填满预览框而裁切用户内容。文字区域在预览与操作之间分配，长文件名与路径按可用宽度省略；正文和省略号使用相同的字体与 DPI。

窗口尺寸先受当前工作区约束，再计算内容区域。按钮按本地化文字的自然宽度分配，不能通过放大所有按钮或强制极窄宽度解决长译文。只有需要翻页时才显示分页操作；空列表、加载失败和操作反馈保留明确状态。

行、预览和按钮的绘制与点击共享几何信息，滚动偏移也参与同一套计算。尺寸改变时重算布局与命中，不能出现可见按钮位置已经变化、点击区域仍停在旧位置的情况。调整显示密度不得改变归档范围、图片/文件复制分流或回收站确认语义，业务边界见 [媒体历史](media-history.md)。

## 窗口移动与 DPI

窗口初次打开时按默认尺寸居中；之后的位置由用户拖动和 Windows 窗口管理决定。刷新列表、收到后台预览或重排内容不能再次执行初始居中。内容列的居中与桌面窗口的位置是两个独立的布局问题。

跨不同缩放比例的显示器时，Windows 通过 `WM_DPICHANGED` 提供新 DPI 以及建议的屏幕位置、尺寸。旧窗口框架应应用这一建议矩形；Qt 产品则由平台插件处理原生窗口与 DPI，业务控件使用 Qt 逻辑坐标，避免第二次手动缩放或再次改写原生位置。两者都不能用原显示器的位置覆盖目标位置，也不能把副屏的负坐标当成无效位置。行为依据见微软 [WM_DPICHANGED 文档](https://learn.microsoft.com/en-us/windows/win32/hidpi/wm-dpichanged)。

鼠标捕获还需要区分所有者。列表按钮按压和滚动条拖动属于应用自己发起的客户端操作，可以在 DPI 改变时取消；标题栏拖动与窗口边缘缩放由 Windows 的原生移动循环管理。仅判断捕获 HWND 是否等于当前窗口，无法证明捕获属于列表，不能据此无条件释放捕获。释放必须与应用自己的捕获状态对应，避免在跨屏时打断原生拖动而使窗口闪跳。平台 API 边界见 [ReleaseCapture](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-releasecapture)。

窗口消息回归应同时检查目标位置、尺寸和捕获状态；真实双屏验收还需观察连续拖过屏幕边界、松开鼠标、反向拖回与再次操作。两类证据分别记录，具体要求见 [验证边界](validation.md)。

## 语言下拉框与弹层

语言选择是一个完整控件。触发器和展开列表必须使用同一套字体、颜色、间距和状态，避免按钮与菜单分别采用两种密度。弹层宽度与触发器协调，边缘受当前显示器工作区约束；下方不足时向上展开。选项过多时在弹层内部滚动，不扩大整个设置窗口。

触发器的语言值与箭头分别布局，箭头保留固定尾部位置；当前语言在列表中有明确勾选标识。选项使用单行短名称，悬停与键盘高亮遵循同一视觉规则。“获取更多语言”是独立操作，与语言值通过分隔区分，不能作为语言写入配置。

方向键只移动高亮，点击或 Enter 才确认语言并关闭弹层。Esc 和点击外部取消展开，不修改当前语言。切换页面、关闭设置、失去所属窗口或 DPI 变化时关闭或重新定位弹层，不能让它留在旧坐标。

弹层的绘制与命中使用相同坐标、滚动偏移和 DPI；不能只移动画面而保留旧点击区域。语言变更会重建页面，提交回调需遵守窗口生命周期，避免在原事件尚未结束时继续访问已销毁节点。弹层不拥有独立于设置窗口的业务状态。

## 本地化与后续扩展

设置标签保持简洁；长路径按实际可用宽度省略，完整路径由提示或打开操作提供。译文过长时调整控件可用宽度和布局，不能一律压缩到小于辅助字号。通用、快捷键与关于页面使用同一主题和对齐规则，新设置不得为自身加入额外强调色或随意扩大整页。

设计验收查看真实 Windows 渲染，至少覆盖中英文、语言弹层展开、长路径和 100% / 125% / 150% 比例。源码常量符合本表只能证明设计意图；实际截图、命中、键盘和跨屏行为的证据分别按 [验证边界](validation.md) 记录。
