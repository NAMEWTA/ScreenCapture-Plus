# Qt 设置、关于与媒体历史

`SettingsWindow`、`AboutPanel` 和 `HistoryWindow` 是 Windows 与 Linux 共用的
Qt Widgets 组件。它们接收宿主的值快照，发送用户命令，不读取配置文件、扫描媒体
目录、解码视频、注册全局热键、删除文件或发起网络传输。应用服务负责这些操作和
真实完成结果，窗口负责显示、输入、确认和焦点。

## 现有实现的复用

设置保留 General、Shortcut、About 三页和现有语言键；历史保留每页 20 项、84
逻辑像素行高、等比预览、尾部复制/定位与原有键盘操作。设置与历史共用
`SettingsMetrics` 和 `DesktopTheme`。旧 Windows `SettingsTheme` 同时读取
`SettingsMetrics`，迁移期间不存在另一份色值、字号或间距定义。编辑器 44/24
工具区仍使用自己的 `ToolbarMetrics`。

控件使用系统字体和明确的逻辑像素字号，不继承两个系统不同的默认 point 大小。
长路径仅在绘制时省略；宿主收到的完整值、提示与可访问名称保持原样。正常控件
使用 Qt 布局、焦点链和滚动条，窗口的位置不因刷新、语言更新或缩略图完成而重置。
初次居中由应用装配负责。

快捷键策略从原 `WinSettingShortcut` 提取到标准库 `Core::ShortcutKeys`，旧页面
和 Qt 页面直接调用同一规则。字母、数字及编辑键必须有修饰键；已有保留组合继续
拒绝。左右 Win/Meta 键先合并再校验，防止同时按下两键形成 `Win+Win+L` 而绕过
原有 `Win+L` 限制。实际键名支持、占用冲突与注册结果仍由平台服务决定。

Qt 组合键输入直接使用 `QKeySequenceEdit`，语言弹层直接使用 `QComboBox` 和
`QListView`。读取了固定 Qt 6.12.1 源码的完成、失焦、弹层定位和激活路径：

- [qkeysequenceedit.cpp](https://github.com/qt/qtbase/blob/5af1a37e31a869cd6eb8a73d82e2c71a450e6634/src/widgets/widgets/qkeysequenceedit.cpp)
- [qcombobox.cpp](https://github.com/qt/qtbase/blob/5af1a37e31a869cd6eb8a73d82e2c71a450e6634/src/widgets/widgets/qcombobox.cpp)
- [qwidget.cpp](https://github.com/qt/qtbase/blob/5af1a37e31a869cd6eb8a73d82e2c71a450e6634/src/widgets/kernel/qwidget.cpp)

本组件通过公开 API 调用 Qt，没有复制 Qt 私有实现。Qt 自身的版本、许可证和
分发义务由依赖锁与第三方许可清单统一记录。适配保留原项目的交互：语言方向键
只移动高亮，点击或 Enter 提交，Esc 取消；“获取更多语言”是独立动作。键盘捕获
以一个组合为单位，首次释放按键后提交候选；Esc、切页和失焦退出捕获。

`WindowDeactivate` 在 `QWidget::event()` 分发，不能放进只接收状态变化的
`changeEvent()`。设置窗口在 Qt 向子控件转发失活前恢复宿主快捷键，并在直连信号
返回后检查窗口是否仍然存在；宿主同步关闭或销毁视图时不能继续调用基类或子控件。

## 设置与更新的真实状态

`DesktopTypes` 中的设置快照表示服务已经生效的值和实际能力。控件的候选值通过
单调 token 请求变更，等待期间禁用冲突操作；失败、取消或旧回调不能显示为保存
成功。宿主回送实际有效快照，失败后据此恢复控件，而不是猜测磁盘或系统状态。
设置窗口不自己读取 `Version.props`，版本由统一应用版本入口注入。

局部键盘捕获通过 `shortcutCaptureActive` 告知宿主暂时停止触发全局截图。系统
管理的快捷键使用同一个页面，由宿主能力选择弹出桌面授权窗口；组件不会声称
本地录到的组合已经获得 Wayland 或系统许可。

About 观察应用级更新状态。明确点击才请求下载，已知总长度显示真实百分比，未知
长度显示不定进度；校验失败显示对应错误，下载后定位使用宿主回送的完整文件路径。
关闭设置只是结束视图订阅，不应取消或重启应用级下载。

## 历史快照、缩略图与清理

列表直接使用 `Media::Entry`，包括服务确认的文件身份和修订快照。窗口每页只请求
至多 20 个、最大 320×320 的封面，接收时核对页代次、完整路径和 `FileSnapshot`。
旧页面、重载前的结果、被替换文件及超出尺寸预算的结果不能写入当前显示缓存。
没有封面时显示实际媒体类型；不会用生成的图像冒充视频内容。

复制、预览、定位和发送只向宿主传递当前条目的值快照。图片/文件复制分流仍由
`Entry::copyAsFile()` 所表达的媒体类型决定；窗口不再实现第二份剪贴板或文件
准入逻辑。命令等待期间不显示“已复制”，只有匹配 token 的成功结果才显示。
失败保留列表。关闭历史窗口不会发送任何取消全局传输的命令。

清空操作先显示非阻塞、默认取消的确认框。确认后发送当时的完整列表快照，不是
当前一页，更不是重新扫描出的所有文件。宿主逐项取得 `reserveRemoval()`，复核
身份后交给回收站服务。需要永久删除时必须第二次确认；该确认只接受原已确认快照
的子集，拒绝插入新路径或变更身份。取消和失败后重新请求剩余列表，不删除另存
副本、无关文件或子目录。

宿主必须将后台回调投递到 GUI 线程，并使用窗口作为 Qt connection/queued
callback 的上下文。`viewClosed()` 用于解除该视图的订阅；后台媒体与传输的所有权
始终在应用服务，不能让一个关掉的列表窗口销毁全局任务。

## 验证范围

`shortcut_keys_tests.cpp` 是可独立 C++20 编译的策略测试。Qt 控件测试在
`desktop_component_tests.cpp` 中使用真实窗口、鼠标/键盘事件、组合键控件、语言
弹层和删除确认框，检查 token、失败恢复、有限缩略图批次、重载、翻页、关闭与
更新状态，并保存实际控件 PNG；取消键盘捕获的直连宿主回调即使销毁设置窗口，
失活事件也不能继续访问已销毁的控件。列表 DTO 是明确标记的组件测试输入，不代表
文件传输或归档服务已经运行成功。

这些测试不替代应用服务装配、真实文件复制/回收、Portal 授权、中文输入法候选窗、
物理混合 DPI、双屏拖动或安装升级验证。实际构建与运行证据仍归
[验证边界](validation.md) 和 [迁移边界](qt-migration.md) 记录。
